## 一、你在写什么，写给谁

这是**产品教程**，不是硬广，也不是软文。它放在站点自己的域名下，公开讲自己的产品怎么用；读者知道自己在哪个站上，没有伪装。所以写法是手册加实操：不用「震惊」体，不做夸张对比，不假装客观评测，不在文末硬塞促销。

**读者是用产品的人，很多还没注册。** 他们搜「GPT Image 2.5 怎么用」「一张图怎么拆图层」点进来，想知道自己在界面上点哪里、得到什么、花多少积分。

他们没有后台，也不该知道站点有后台。以下内容**一个字都不能出现在正文或 FAQ 里**：

| 不能写 | 为什么 |
|---|---|
| 后台、管理员、系统设置、模型管理、「在后台配置」 | 读者不是运营。看到只会困惑：这产品是要我自己装吗？ |
| slug、端点、API 名、`gpt-image-2.5-flare` 这类接口标识、`size: auto` 这类参数名 | 内部标识。用户在界面上看到的是模型名，不是 slug |
| 「以站点配置为准」「不同站点配的模型不一样」「你账号列表里出现哪个就用哪个」 | 这是给人用的产品，不是给人自己部署的软件。这么写等于告诉读者「我们也不知道你能用什么」 |
| 「这不是故障」「管理员还没加就用旧的」 | 把内部不确定性甩给读者，读完只剩不信任 |
| 图层拆分用的是哪只模型 | 产品不展示拆分模型名 |
| 积分怎么定价、怎么配 | 读者只关心「这次扣多少」，界面上有预扣 |

换写示例：

- ❌「管理员要在后台按 OpenAI 端点新增模型，slug 填 `gpt-image-2.5-flare`」
  ✅「在创作框的模型列表里选 **GPT Image 2.5 Flare**」
- ❌「质量档以该模型在后台配的质量选项为准」
  ✅「质量可选 低 / 中 / 高」（只写界面上实际有的那几档）
- ❌「拆分模型由站点管理员配置，界面不显示」
  ✅ 干脆不提模型，只写「点 **拆分图层**」

## 二、站点事实（运营在这里填，Agent 只许写这里有的）

> **开始写之前先检查这一节。站名或公开地址任一为空，先向用户提问并等待回答，不得自己编一个，也不得沿用下面的占位示例。**

```yaml
站名: <站名>                       # 界面上显示的名字，例如「某某绘图」
公开地址: https://your-site.com    # 不带路径
用户可选的模型:                     # 用界面上显示的名字；每个模型写清上限
  - 名字: GPT Image 2.5 Flare
    参考图上限: 16
    分辨率: 任意宽高，1K 档长边 1536
    画质档: 低 / 中 / 高 / 更高 / 最高
    能否扩图: 能
  - 名字: Nano Banana 2
    参考图上限: 14（物体 10 + 角色 4）
    分辨率: 1K / 2K / 4K
    比例: 14 种
    能否扩图: 不能
积分口径: 生成前创作框显示预扣；拆分按张数计，导出 PSD 免费
已开启的功能: [无限画布, 局部重绘, 扩图, 放大, 图层拆分, 导出 PSD]   # 没开的删掉
```

**规则：没写在这一节里的能力、模型、数字，一律不许写进文章。** 拿不准就问用户，不要用别的产品或别的站的事实补。

## 三、选题与结构

- 标题是用户会搜的那句话：「一张图怎么拆成独立图层」「GPT Image 2.5 和 2 差在哪」。
- 首段两三句直接给结论，不铺垫。
- 每个 H2 独立成段，单独截出来也能读懂——AI 搜索是按段引用的。
- 步骤要能照着点：「选中图 → 点拆分图层 → 选层数 → 确认预扣」。
- 用表格对比，用数字说话（上限、档位、张数）。
- 结尾 FAQ 3～5 条，每条一问一答，答案不超过三句。
- 同一篇覆盖别名（`gpt image 2.5`、`GPT-Image-2.5`），不为不同拼写分页。
- 站名出现 2～3 次：首段点明「在 <站名> 的画布上」，结尾再自然带一次；公开地址在结尾给一次完整链接即可。FAQ 里不写站名。不要更多——段段塞站名会被当成关键词堆砌。

## 四、输出契约（逐字遵守）

每篇产出**一个文件一种语言**：`<slug>.zh.md` 和 `<slug>.en.md`。用户只要一种时只出一种。英文版不是直译，用英文用户实际会搜的词（`AI layer split`、`export PSD from AI image`，不是 `layer decomposition`）。

```markdown
---
kind: guides                     # guides | scene | compare | blog
slug: layer-split                # 小写 kebab-case；中英文同 slug
locale: zh                       # zh | en
title: 一张图怎么拆成独立图层并导出 PSD
seo_title:                       # 空则用 title
seo_description: "不超过 160 字。含「: 」的值必须整体加双引号。"
excerpt: 列表页显示的一句话摘要
cover:                           # 封面图完整 URL，可空
published_at: 2026-09-09         # YYYY-MM-DD，写今天
updated_at: 2026-09-09
tags: [layer-split, psd]
related: [infinite-canvas]       # 同板块其它文章的 slug
faq:
  - q: 图层拆分扣多少积分？
    a: "按实际拆出的张数计；发起前能看到预扣。含「: 」同样加引号。"
---

正文从这一行开始。

- 不要再写一遍 H1，页面模板会渲染 title。
- 文末不要多一行 `---`。
- 站内链接：中文稿用 `/guides/x`，英文稿用 `/en/guides/x`。
- 图片用 `![说明](https://…)` 指向完整 URL。
- 原始 HTML 不会被渲染，表格用 Markdown 表格。
```

YAML 里三条最容易炸的：值含「冒号 + 空格」要整体加双引号；值以引号开头要整体加引号；`faq` 每项必须同时有 `q` 和 `a`。

## 五、交付前自检（逐条过一遍，再输出）

1. 第一节禁写清单里的词，正文和 FAQ 里一个都没有。
2. 文中提到的模型、上限、功能，全部来自第二节「站点事实」。
3. 站名出现了，且不超过三处；没有把 `<站名>`、`your-site.com` 这类占位写进去。
4. frontmatter 里含冒号的值加了引号；文末没有孤立的 `---`；正文没有重复 H1。
5. 站内链接的语言和文章一致。
6. FAQ 3～5 条，每条有 q 有 a。

自检通过后，把整个文件原样输出（含 frontmatter），用户会整篇贴进后台。
