## 安装位置（Agent 执行「帮我安装这个 skill」时读这里）

把本文件和同目录下这些文件一起保存（raw 地址把 `SKILL.md` 换成对应路径即可）：

- `format.md`：技能包格式，唯一的契约
- `validate.mjs`：本地校验脚本（Node.js 18+，无依赖）
- 一个完整示例：`example/minimal-coffee-poster/SKILL.md`、`example/minimal-coffee-poster/examples/01-cover.png`、`example/minimal-coffee-poster/references/layout.png`

放哪里：

- Claude Code：`.claude/skills/draw-skill-author/`（保持上面的相对路径）
- Codex：`.codex/skills/draw-skill-author/`，或把正文追加进 `AGENTS.md`、其它文件放工作目录
- 其它：保存到工作目录，在系统提示里引用本文件

安装后告诉用户：**「说说想做什么技能，或者把要转换的技能文件 / 文本发给我；有示例图、风格参考图的话也一起给我。」**

## 一、你在做什么

Draw Studio 是一个 AI 绘画站点，站内有一个创作 Agent。「技能」是给这个 Agent 的一份做法说明：用户选中某个技能，或者说到相关的话，Agent 就加载技能正文，照着去出图。

运营方可以在后台给全站用户上架**运营技能**。站点后台**不帮忙写、不跑 LLM**，只接受 `format.md` 规定格式的技能包。你的工作是在运营方的电脑上把技能写好、转好、校验好，打成一个 zip，由运营方自己上传：

```
你（Codex / Claude Code） ──写作、转换、校验──► <slug>.zip ──运营方手动上传──► Draw Studio 后台（只校验）
```

你**不连接** Draw Studio，不需要任何密钥，也不上传文件。图片直接放进技能包，由后台转存到站点配置的对象存储。

## 二、开始前要问清的

缺一项就问，不要猜：

1. **做什么技能**：从零写，还是转换一个现成的技能（让用户把文件 / 文本发来）。
2. **用在什么场景**：产出什么、给谁看、用户一般会怎么说（决定简介里的触发说法）。
3. **默认输出**：比例、张数、分辨率有没有固定要求。
4. **图片**：有没有现成的效果图（做示例图）和风格参考图（做参考图）。没有就不放，不要去网上随便找。

## 三、站内 Agent 能做什么（写正文前必须读）

技能只能改变 Agent **怎么用它已有的工具**，不能给它新增能力。站内 Agent 可能用到的工具（是否开启取决于站点配置）：

| 工具 | 用途与要点 |
| --- | --- |
| `generate_image` | 唯一的出图入口，结果自动放到画布。参数：`prompt`、`aspect_ratio`（如 `"3:4"`）、`resolution`（`1K` / `2K` / `4K`）、`size`（自定义像素，如 `1536x864`，部分模型支持）、`count`（1–4）、`transparent_background`（透明底 PNG）、`use_reference_images`（用本回合用户给的图）、`reference_image_urls`（用之前的图或技能参考图） |
| `edit_image` | 放大（`upscale`）或扩图（`outpaint`）已有的图 |
| `view_images` | 看清对话里更早的图 |
| `ask` | 向用户提一个选择题并暂停，适合「先确认标题 / 方案再出图」这类节点 |
| `split_layers` | 把一张图拆成图层 |
| `find_reference_images` | 联网找真实事物的参考图（站点开启联网搜索时） |
| `web_search` / `fetch_page` | 联网查资料（站点开启时） |
| `generate_video` | 生成视频（站点开启视频时；技能一般不要依赖它） |

做不到、不要写进正文的：

- 跑脚本、读写文件、调用外部 API、打开任意网页、安装插件；
- 改变计费、跳过积分确认、改变站点规则；
- 依赖别的技能，或要求 Agent 记住技能之外的东西。

正文里要写清楚**什么时候调用哪个工具、带什么参数**，比如「默认调用 generate_image，`aspect_ratio: "3:4"`、`count: 1`；用户给了照片时设 `use_reference_images: true`」。

## 四、写法

**名称**（中英各一份）：短、能看出产出物，≤ 30 字。英文按母语习惯写，不要逐字翻译。

**简介 summary**（中英各一份，≤ 200 字，单行）：写「做什么 + 什么时候用」，把用户可能的说法写进去，包括不点名技能的说法。Agent 靠这一句决定何时加载技能。

- 好：「做极简风的咖啡新品海报：单杯饮品居中特写、大面积留白、细衬线英文标题配一行中文，竖版 3:4。用户提到咖啡新品海报、饮品上新、极简饮品海报时使用。」
- 差：「咖啡海报技能。」

**输入框提示 placeholder**（可选）：用户选中技能时输入框里的示例说法，可带 `[占位符]`。

**分类 category**：从 `format.md` 的分类表里选；选不准就问用户。

**正文**：Markdown，写给站内 Agent，祈使句。按下面的骨架写，用不上的小节删掉，不要留空标题：

```
# <名称>

## 目标
一句话：产出什么、给谁用。

## 系统能力边界
一张小表：要做的事 → 用哪个工具、带什么参数。写明做不到的事遇到时怎么回应用户。

## 输入
需要用户提供什么（图 / 文案 / 尺寸）；缺了怎么问。

## 流程
分步写；需要用户拍板的步骤写「调用 ask 确认 …」。

## 默认输出
写成 generate_image 的参数（aspect_ratio / resolution / count）；用户当场指定的优先。

## 要点
画面语言、构图、配色、字体气质，每条一句、具体可执行；不写「高级」「好看」这类空话。

## 参考图怎么用
每张参考图借什么、不借什么（有参考图时；和 frontmatter 里的 note 一致）。

## 禁止
这个场景真实会踩的坑。

## 和相近技能的区别
站内可能有类似技能时，写清这个技能适合什么、不适合什么，避免 Agent 选错。

## 成图自检
出图后 Agent 自己对照检查的清单（文字是否准确、主体是否完整、比例是否正确……），不合格时怎么处理。

## 示例
一两组「用户这么说 → 你这么做」。
```

## 五、转换别处的技能

- 提炼**做法与画面语言**，按第四节的骨架重写，不是逐句翻译；原文写得好的风格描述保留用词。
- **丢弃**机制性内容：原 frontmatter 里的 `tools` / `allowed-tools`、文件引用、脚本、「调用 XX API」、MCP / 插件。
- 原文要求站内做不到的事（第三节）：改成站内能做的写法，改不了就删掉。
- **只转换，不添加**：原文没有的规则不要补；原文的风格要求不要「顺手优化」掉。
- 原文多个文件（参考文档、模板）：有用的部分并入正文，正文控制在 20000 字以内，超了优先保留规则、压缩示例。
- 原文里的图片：效果图放 `examples/`，风格参考放 `references/` 并写 note；看不出用途的不放。
- 写完给用户一份清单：保留了什么、改写了什么、删掉了什么（逐条，说明原因）。

## 六、图片

- `examples/`：示例图，最多 6 张，**按文件名排序，第一张是封面**（建议命名 `01-cover.png`、`02-….png`）。会展示给所有用户，选最能代表产出效果的图；没有合适的就不放，运营方可以上架后在后台补。
- `references/`：参考图，最多 4 张，每张在 frontmatter 的 `references` 里写一句 `note`：借什么、不借什么（「借三段式版式与留白，不借菜品」）。站内 Agent 用这个技能出图时会拿到这些图作参考。
- 只用用户给的图，或用户明确同意使用的图。不要放带水印、带他人品牌或版权不明的图。
- 格式 PNG / JPEG / WebP，单张 ≤ 5 MB。

## 七、自检与打包

1. 按 `format.md` 写好 `<slug>/SKILL.md`，图片放进对应目录。
2. 运行校验：

   ```
   node validate.mjs <slug>
   ```

   没有 Node.js 就请用户安装（18 以上），或把下面的检查逐条人工过一遍。必须**全部通过**才往下走；按提示修改后重跑。
3. 打包（`<slug>/` 目录本身放进 zip）：
   - macOS / Linux：`zip -r <slug>.zip <slug>`
   - Windows PowerShell：`Compress-Archive -Path <slug> -DestinationPath <slug>.zip`
4. 自己再通读一遍正文：有没有站内做不到的事、有没有空话、默认输出和简介是否一致。

## 八、交付

告诉用户：

1. zip 文件的位置。
2. 上传位置：Draw Studio 后台 → Agent 技能 → 运营 → 新建技能 → 上传技能包。同名 slug 已存在时后台会提示「替换现有技能内容」。
3. 上传后是**草稿**：管理员在工作台的技能选择器里能看到并试用；确认效果后回后台点「发布」，全站用户才看得到。
4. 转换类任务附上第五节的「保留 / 改写 / 删除」清单。
